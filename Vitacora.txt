Resumen

Comparación de tasas de crecimiento modal (k≈40 rad/m, r/R=0.3) entre dos ejecuciones con Bz alto y Bz bajo, usando salidas separadas y un script comparador reproducible.

Setup

Código: ZPinchSim (toy MHD 2D).

Resolución/tiempos: iguales en ambos casos (mismos Nr, Nz, t_end, output_every).

Campos escritos: rho, p, vr, Bth + meta por snapshot.

Carpetas de salida:

Alta: ./data_runs/Bzhigh (Bz0 = 1)

Baja: ./data_runs/Bzlow (Bz0 = 0.1)

Análisis: _modes_core.py + step5_compare_modes.py.

Comandos usados
# Ejecutar runs desde build/Release
Remove-Item -Recurse -Force .\data_runs\Bzhigh
.\zpinch_run.exe .\configs\run2d_modes_Bzhigh.yaml

Remove-Item -Recurse -Force .\data_runs\Bzlow
.\zpinch_run.exe .\configs\run2d_modes_Bzlow.yaml

# Comparación
python .\viz\step5_compare_modes.py --high-dir .\data_runs\Bzhigh --low-dir .\data_runs\Bzlow --quiet

# Evidencia opcional

Nota sobre vmax y dt

En el log, vmax=1000 (constante) con dt=5e-08. Esto ocurre porque:

En el código se aplica un tope VMAX_GUARD = 1e3, y luego vmax = min(vmax_real, 1e3).

También hay un tope de dt: DT_MAX = 5e-8, y termina dominando, dejando el paso de tiempo constante.

¿Está “mal”?
No necesariamente para el Paso 5: como ambos runs usan el mismo dt y el mismo cap de vmax, la comparación relativa (Δgrowth) es válida.
Pero sí oculta diferencias en velocidades características entre casos (por ejemplo, variaciones de la rápida magnética por cambios en Bz). Para estudios más físicos o para producción, conviene:

Registrar ambas magnitudes: vmax_raw (sin cap) y vmax_capped (tras el cap), y mostrarlas en el log.

Subir o eliminar VMAX_GUARD para que el CFL real controle el dt (o al menos fijarlo a un valor suficientemente alto para que no sea el limitante).

Ajustar DT_MAX (hacerlo grande o quitarlo temporalmente) para que el criterio CFL sea el dominante.

Verificar que el CFL efectivo sea < 1 en todo el dominio.
